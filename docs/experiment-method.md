# 实验方法与数据口径

## 环境

| 项目 | 固定值 |
| --- | --- |
| 测试日期 | 2026-11-24 |
| 平台 | Windows、Docker Desktop、SQLite，分别运行独立测试实例 |
| AxonHub | `looplj/axonhub:v1.0.0-rc.4` |
| New API | `calciumion/new-api:v1.0.0-rc.51` |
| 数据路径 | 本地客户端 → 网关 → Docker 内部模拟服务 |
| 协议 | OpenAI 兼容 `POST /v1/chat/completions`，流式样本启用 `include_usage` |
| 模型别名 | `auto`，主路由指向 `lab-gpt-v1`，备用指向 `lab-deepseek`，换代用 `lab-gpt-v2` |

两条渠道都使用 OpenAI 兼容格式。模型和响应文本是测试固定值。工具用例只验证函数名与参数透传。主要的客户端响应来自串行请求，New API 独立批次另跑了 4 并发、12 条短请求。

## 用例设计

1. 正常请求应命中模拟 GPT。用上游记录确认实际模型，而不是只看对外返回的模型字段。
2. 模拟主渠道返回 503、429、401 或延迟 3 秒。429 带 `Retry-After: 2`。同时令两条渠道返回 503，确认网关的错误边界。
3. 分别让上游在流式首事件前出错、发出文本后断开。核对 HTTP、正文、`finish_reason`、`[DONE]`、usage、真实上游尝试数及结算记录。
4. 单独改变 GPT 上游映射，客户端保持请求 `auto`。工具场景分别走主链与回退链。
5. 使用正常、无效、停用或受限 Key 发请求。普通用户或项目成员与管理员的结果分开记录。
6. 给完整模拟响应固定 **1,200 输入、500 输出、200 缓存输入**，缓存词元已包含在输入中。将实例使用统计与手算费用对照。

## 复现步骤

在本机启动对应固定版本，使用独立数据库和自建 OpenAI 兼容模拟服务。将模拟服务限制在 Docker 网络，网关仅发布到回环地址。用两条渠道分别映射到模拟 GPT 与模拟 DeepSeek。

- **AxonHub**：创建 `auto` 模型并关联主、备渠道，优先级为 0 和 1。主要批次最多切换一次，同渠道额外重试为 0。复测 429 同渠道间隔时，允许一次同渠道重试、配置 200 ms 间隔，并把 429 加入该渠道可重试状态。
- **New API**：两条渠道都把对外模型设为 `auto`，配置不同上游模型映射，主优先级 10，备优先级 1，最多重试一次。转发超时设为 1 秒。单渠道 429 用例执行前临时停用备用，结束后恢复。
- **采集**：每次请求携带唯一的模拟文本标记，在客户端与上游日志记录同一标记。时间差用模拟服务日志中同一标记的连续事件计算。上游未命中的鉴权或模型错误应无上游记录。
- **对账**：完整样本核对 1,700 总 Token。流式中断单独按实际客户端报文和落库行为记录。按项目、Key、用户或渠道选择取证路径。

实验通过公开版本的管理接口配置。仓库为报告和实验数据集，可按上述用例重新实现模拟服务。

## 数据说明

[逐条 CSV](../evidence/request-results.csv) 与 [归一化 JSON](../evidence/experiment-evidence.json) 可用 `gateway + marker` 关联。JSON 中 `offset_ms` 以首个上游事件为起点。拒绝在网关内部的请求，其上游数组为空。CSV 中空字段代表该批未采集或该字段对用例不适用，不能按零或 false 计算。

| 数据集 | 样本数 | 范围 |
| --- | ---: | --- |
| `axonhub-repeat` | 213 | 四轮重复验证。三轮完整费用对账，两轮普通项目成员验证 |
| `new-api-standalone` | 100 | 四轮基础用例和一组独立权限、额度、备用关闭、模型换代及短并发用例 |

展示页的总账可能包括前后多轮运行。报表单轮统计按明确的批次、窗口或 Key 对照。样本数是复现证据，不能推导生产成功率、供应商稳定性或实际吞吐。
